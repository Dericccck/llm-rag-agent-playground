# 03 Agentic Design Patterns 学习摘要

## 对应 Notebook
- `03-semantic-kernel.ipynb`

## 这一节在做什么
这一节开始强调：Agent 不只是“能回答”，还要“按你设计的规则回答”。

所以它重点在演示：
- 如何通过系统提示词设计 Agent 的行为模式
- 如何让 Agent 遇到不同类型请求时遵循更明确的流程

## 这里要分清三个角色

### `qwen-max`
- 负责理解用户需求
- 负责根据系统提示词执行既定行为
- 负责组合最终回答

### `DestinationsPlugin`
- 负责提供旅行目的地相关数据
- 是 Agent 可调用的辅助能力

### `AGENT_INSTRUCTIONS`
- 这是这一节真正的重点
- 它定义 Agent 该怎么做，而不是只定义它“是谁”

## 这个 notebook 里的实现工序

### 1. 先定义工具
和前面类似，先定义 `DestinationsPlugin`。

### 2. 接入模型
通过 DashScope 的兼容接口连接 `qwen-max`，再交给 `OpenAIChatCompletion` 封装。

### 3. 重点：设计系统提示词
这里写了一段更完整的 `AGENT_INSTRUCTIONS`，核心规则包括：
- 如果用户指定目的地，就必须按这个目的地规划
- 只有用户没有明确偏好时，才随机推荐目的地
- 对话开始时要先自我介绍
- 告诉用户可以问哪些类型的问题

这一节本质上是在告诉你：
Agent 的“行为模式”很多时候不是写在 Python 逻辑里，而是写在系统提示词里。

### 4. 创建 Agent
创建 `TravelAgent`，并把上面的系统提示词灌进去。

### 5. 测试多轮交互
然后通过多轮对话测试：
- 用户先要一个旅行方案
- 用户不满意，再要求换一个方案

观察 Agent 是否会沿着你预先设计的规则走。

## 整个工序可以简化成
定义工具 -> 配置模型 -> 编写行为规则提示词 -> 创建 Agent -> 用户发起请求 -> 模型按规则解释请求 -> 调用工具或直接回答 -> 多轮对话里持续遵循同一套规则

## 这一节的关键收获
- Design Pattern 在这里主要体现为“行为约束模式”。
- 一个好 Agent 的关键，不只是模型强，而是规则清楚。
- 系统提示词可以承担：
  - 角色定义
  - 决策优先级
  - 流程约束
  - 开场白与交互风格
