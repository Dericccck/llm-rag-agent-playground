# 13 Agent Memory 学习摘要

## 对应 Notebook
- `13-agent-memory-chromadb.ipynb`

## 这一节在做什么
这一节是在实现一个“有长期记忆”的 Agent。

重点不是普通聊天上下文，而是：
- 用户这次说过的偏好
- 过几天再来时还能记住
- 并且能在新问题下，把相关旧记忆找回来继续用

## 先回答一个关键问题
不是“把记忆存在向量模型里”。

更准确地说是：
- 记忆文本先被 embedding 模型向量化
- 向量和原文再被存进向量数据库

所以：

### `qwen-max`
- 负责聊天
- 负责理解用户意图
- 负责决定什么时候存记忆、什么时候查记忆

### `bge-small-en-v1.5`
- 负责把文本转成向量
- 它只是 embedding 工具，不是存储位置

### `ChromaDB`
- 负责真正存储向量、原始文本和 metadata
- 它才是记忆仓库

### `Mem0`
- 负责把“存记忆 / 查记忆”这套流程封装起来
- 它站在 Agent 和向量库之间，像一个记忆管理层

## 这个 notebook 里的 memory 流程是怎样的

### 1. 初始化记忆系统
代码里先通过：
- `Memory.from_config(mem0_config)`

创建一个 `Mem0` 对象。

这里告诉 Mem0 三件关键事：
- 聊天模型用 `qwen-max`
- embedding 模型用本地 `bge-small-en-v1.5`
- vector store 用本地 `ChromaDB`

也就是说，这里已经把“聊天”“向量化”“存储”三层职责拆开了。

### 2. 初始化旅行知识库
除了记忆库，这个 notebook 还单独建了一个旅行酒店集合。

这部分也是 ChromaDB，但用途不同：
- 一个集合用来存酒店和目的地检索数据
- 另一个集合给 Mem0 存用户长期记忆

这点很重要：
同样是 ChromaDB，可以承载不同类型的向量数据，不一定只有一种集合。

### 3. 定义记忆型插件
代码里写了一个 `TravelBookingPlugin`，把两类能力封装进工具里：

#### 酒店搜索能力
- 去旅行向量库里查酒店

#### 用户记忆能力
- `store_user_preference(...)`
- `get_user_preferences(...)`
- 以及相关检索逻辑

这个插件相当于把“业务查询”和“记忆管理”一起暴露给 Agent。

### 4. 用户在对话中提供偏好
例如用户会说：
- 这是周年旅行
- 喜欢浪漫目的地
- 喜欢 fine dining 和 spa
- 有行动不便问题
- 是素食
- 对坚果过敏

这些信息里有些是一次性问题，有些则很适合长期记住。

### 5. Agent 决定要存哪些记忆
在对话过程中，`qwen-max` 会结合插件能力，把值得长期保留的信息交给记忆层。

也就是类似：
- 用户偏好
- 饮食限制
- 预算倾向
- 出行习惯

这一步不是直接写数据库，而是走插件，再走 Mem0。

### 6. Mem0 写入记忆
当执行：
- `self.memory.add(preference, user_id=user_id)`

内部大致会做这些事：

#### 第一步：接收原始记忆文本
比如：
- `I am vegetarian with a peanut allergy`

#### 第二步：调用 embedding 模型向量化
用本地的：
- `bge-small-en-v1.5`

把这段文本变成向量。

#### 第三步：写入 ChromaDB
把下面这些内容一起存进去：
- 向量
- 原始文本
- 用户 ID
- 其他 metadata

这一步完成后，长期记忆就真正落库了。

### 7. 用户以后再次提问
当用户过几周后回来再说：
- 我们又想计划一次旅行

Agent 会尝试去找与当前问题相关的历史偏好。

### 8. Mem0 检索记忆
当调用搜索逻辑时，内部大致流程是：

#### 第一步：把当前查询文本向量化
例如当前问题里提到：
- 家庭旅行
- 酒店推荐
- 饮食限制

查询文本会先被 embedding。

#### 第二步：去 ChromaDB 做相似度检索
到记忆集合里找：
- 和当前问题最接近的历史记忆向量

#### 第三步：返回命中的历史记忆
例如找回：
- 用户是素食
- 对坚果过敏
- 喜欢浪漫体验

### 9. Agent 用记忆生成个性化回复
最后 `qwen-max` 会把：
- 当前问题
- 新上下文
- 召回的历史记忆

一起考虑，生成类似这种回答：
- 你之前提到你们偏爱浪漫目的地，而且有素食与坚果过敏限制，所以我优先推荐……

## 整个工序可以简化成
用户对话 -> Agent 判断哪些信息值得长期记忆 -> `Mem0.add()` -> `bge-small-en-v1.5` 向量化 -> ChromaDB 存储向量和原文

新问题到来 -> `Mem0.search()` -> 当前问题向量化 -> ChromaDB 相似度检索 -> 返回相关记忆 -> `qwen-max` 结合记忆生成个性化回答

## 这一节的关键收获
- 长期记忆不是只靠聊天线程保存，而是独立的记忆层。
- embedding 模型不负责存储，它只负责把文本变成可检索向量。
- ChromaDB 不负责理解语义，它负责存和查。
- `Mem0` 的价值在于把“记忆提取、向量化、存储、召回”这一套流程统一封装起来。
