# 09 Metacognition 学习摘要

## 对应 Notebook
- `09-semantic-kernel.ipynb`

## 这一节在做什么
这一节是在演示一个“会记住自己前面怎么想、会根据用户反馈调整行为”的 Agent。

这里讲的 metacognition，不是严格学术意义上的自我意识，而是更工程化的意思：
- Agent 会跟踪用户偏好
- 会在后续回答里显式使用这些偏好
- 会根据反馈修正建议

## 这里要分清三个角色

### `qwen-max`
- 负责理解用户当前请求
- 负责维护偏好相关的推理逻辑
- 负责决定什么时候调工具、怎么组织回答

### `DestinationsPlugin`
- 负责提供外部旅行数据
- 里面定义了：
  - `get_destinations`
  - `get_flight_times`

### `ChatHistoryAgentThread`
- 负责保存上下文
- 它让 Agent 可以根据前面的对话继续思考，而不是每一轮都从零开始

## 这个 notebook 里的实现工序

### 1. 定义旅行工具
插件里提供：
- 可选旅行目的地
- 某个目的地的航班时间

### 2. 编写强约束提示词
这一节最关键的是提示词规则。

它要求 Agent：
- 第一次问航班时，要先问用户偏好时间
- 一旦确定偏好，后续不要重复问
- 后续给新目的地建议时，要自动沿用这个偏好
- 回答时明确说“我是基于你之前偏好做出推荐”

也就是说，这里的“元认知”大部分是通过提示词在模拟一个内部偏好对象。

### 3. 创建 Agent 并开启流式响应
接着创建 Agent，并通过 `invoke_stream` 跑多轮对话。

### 4. 在多轮对话中追踪函数调用
代码会把流式内容拆开看，包括：
- 函数调用
- 函数返回结果
- 最终文本回答

这样你能看到 Agent 不是黑盒，而是能观察它内部什么时候查航班、什么时候继续回答。

### 5. 继续复用旧线程
后面又通过 `continue_chat()` 在同一个线程上继续问：
- 帮我订一张去巴黎的票

此时重点观察：
- Agent 是否还记得之前用户喜欢早班/晚班
- 它是否真的在新目的地上复用旧偏好

## 整个工序可以简化成
用户首次提问 -> Agent 询问偏好 -> 偏好写入对话上下文 -> 后续问题继续沿用偏好 -> 必要时调用航班工具 -> 结合上下文生成更个性化的回答

## 这一节的关键收获
- 这里的“记忆”主要还是线程级上下文记忆，不是长期向量记忆。
- Metacognition 在工程实现上，常常表现为：
  - 跟踪状态
  - 自我约束
  - 根据反馈调整
- 这个 notebook 也能看出一个现实问题：
  - 仅靠提示词维护偏好，稳定性并不总是足够强。
